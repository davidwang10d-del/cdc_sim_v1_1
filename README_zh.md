# CDC Sim 中文完整使用说明

[English README](README.md) | 从第一次安装到主席团实际操作的零基础指南

CDC Sim 是用于模拟联合国危机委员会的浏览器军事与政治推演系统。主席团可以挂载剧本、在地图上下达部队任务、处理战斗与支援任务、记录危机裁定、修改民意和占领、保存检查点，并导出 SITREP（态势报告）。

> **开始前必须看懂：**本项目里的 **DLC 指一个保存在本机的剧本文件夹**。它不是收费扩展包，不需要 Steam，不需要账号，也不需要产品密钥。系统必须找到至少一个有效 DLC 才能进入战术地图。本项目自带可游玩的 `afghan` 剧本和用于制作新剧本、默认不显示的 `_template` 模板。

## 一、电脑和软件要求

如果你不熟悉 Python，请严格使用下面的配置，不要擅自换版本。

| 项目 | 必须或建议使用的内容 | 原因 |
| --- | --- | --- |
| 操作系统 | 64 位 Windows 10 或 Windows 11 | 项目自带的一键 `.bat` 文件是 Windows 脚本。 |
| Python | **64 位 Python 3.12.x** | 安装脚本会明确请求 3.12；锁定版本的 NumPy、Rasterio、Pillow 不保证支持 Python 3.13/3.14。版本更“新”不代表兼容。 |
| 浏览器 | 最新版 Edge、Chrome 或 Firefox | 操作界面在浏览器中运行，但推演服务器仍在本机。 |
| 第一次安装时的网络 | 必须 | `pip` 需要下载 `requirements.txt` 中的依赖。 |
| 正常使用时的网络 | 当前默认界面需要 | Leaflet、底图瓦片和编辑器的 JSZip 来自外部 CDN。后端推演本身在本机。 |
| 硬盘空间 | 至少预留 1 GB | `.venv` 大约 200 MB；可选 GIS 文件可能增加数百 MB。 |
| 管理员权限 | 通常不需要 | Python 需要先安装；CDC Sim 的依赖只安装在项目目录内。 |

依赖版本为 Flask 3.0.0、NumPy 1.26.0、Pillow 10.0.1、Rasterio 1.3.9、Requests 2.31.0 和 Matplotlib 3.8.0。不要逐个手动安装，安装脚本会统一处理。

## 二、第一次安装：一步一步照做

1. 下载或复制 **整个** CDC Sim 文件夹。不要只复制两个 `.bat` 文件，也不要把单独文件散放在桌面。
2. 从 [python.org](https://www.python.org/downloads/) 安装 **64 位 Python 3.12.x**。
3. 在 Python 安装器中勾选 **Add python.exe to PATH**。建议同时安装 Python Launcher（`py.exe`）。
4. 用文件资源管理器打开 CDC Sim 文件夹。确认同一层能看到：
   - `INSTALL_OR_REPAIR.bat`
   - `START_CDC_SIM.bat`
   - `server.py`
   - `requirements.txt`
   - `dlc` 文件夹
5. 双击 `INSTALL_OR_REPAIR.bat`。
6. 如果 Windows SmartScreen 弹出提示，先确认该文件确实来自你信任的项目副本；确认后再选择“更多信息 → 仍要运行”。
7. 不要关闭黑色安装窗口。脚本会创建 `.venv`、升级安装工具、安装依赖并运行 `pip check`。过程可能需要几分钟。
8. 只有最后显示 `Install/repair complete.` 才算成功。如果出现红字或错误，请先看本文的“常见问题”。
9. 按任意键关闭安装窗口。

批处理不会把这些 Python 包全局安装到系统中；它们全部位于项目的 `.venv` 文件夹。以后修复依赖时可以直接再次运行 `INSTALL_OR_REPAIR.bat`，不会删除 DLC 或存档。

## 三、第一次启动：一步一步照做

1. 双击 `START_CDC_SIM.bat`。
2. 黑色服务器窗口会打开。**整个使用期间必须保持这个窗口开启。**关闭它就等于关闭 CDC Sim。
3. 等待窗口显示 Flask 服务地址。脚本不会自动打开浏览器。
4. 在浏览器地址栏输入 [http://127.0.0.1:5000/status](http://127.0.0.1:5000/status)。`127.0.0.1` 代表“这台电脑”，不是公网网站。
5. 确认页面显示 **Ready for committee use**：没有缺少的 Python 包、至少有一个有效 DLC、无无效 DLC。缺少可选 GIS 文件不等于 DLC 无效。
6. 点击 **Open dashboard**，或打开 [http://127.0.0.1:5000/zh](http://127.0.0.1:5000/zh)。
7. 在“可用战区模组”列表中点击要使用的剧本。自带剧本通常选择 `afghan`。以 `_` 开头的 `_template` 是模板，所以不会出现在列表里。
8. 等待地图和部队出现。GIS 面板中琥珀色 `OFF · DEFAULT` 表示正在使用安全默认值；红色表示配置了文件但无法读取，需要检查。
9. 确认顶栏显示 `[ 已暂停 ]`。
10. 点击 **存档**，在“检查点 1”下面点击 **保存到此处**。这样在任何人误操作前就有一个干净的初始状态。

如果浏览器显示无法连接，通常是服务器窗口已关闭、服务器尚未启动完成，或 5000 端口已被其他程序占用。

## 四、以后每次启动和正确关闭

每次重新开始：

1. 双击 `START_CDC_SIM.bat`。
2. 保持黑色窗口开启。
3. 打开主界面。
4. 先挂载需要的 DLC。挂载永远加载 DLC 编写者设定的初始状态，**不会自动恢复上次进度**。
5. 点击 **存档**，在需要的检查点上点击 **恢复此检查点**。恢复后系统一定处于暂停状态。

正确关闭：

1. 点击暂停按钮 `⏸`。
2. 打开 **存档**，保存到目标检查点；如果已有内容，确认覆盖。
3. 如有需要，打开 **MUN** 导出最终 SITREP。
4. 切回黑色服务器窗口，按 `Ctrl+C`。
5. 关闭浏览器标签页。**关闭浏览器不会自动保存。**

### 如何看懂时钟和部队数值

时钟格式为 `Dxx HH:MM:SS`。例如 `D00 06:30:00` 表示剧本第 0 天 06:30，不是电脑当前时间。只有点击 **运行** 后，推演时间才会前进；速度倍率决定推演时间相对真实时间推进多快。暂停会冻结移动、战斗、恢复、建设、占领变化、任务飞行/进度和临时效果倒计时。暂停时仍可选择部队、打开面板、保存和准备命令。

| 界面数值 | 最直白的含义 | 必须记住 |
| --- | --- | --- |
| **Status / 状态** | 部队此刻正在做什么，例如待命、移动、防御、建设、炮击、出击或返航。 | 状态是当前活动；Operational Order 面板中的任务和姿态才是权威命令。 |
| **Personnel Alive / 现存兵力** | 直接战斗和任务伤亡后仍存活的当前人数。 | 这是人数，不等于战斗力。少量但战备良好的部队可能强于疲惫的大部队；变为 `0` 时没有有效现存兵力。 |
| **Morale / 士气** | 部队继续作战的意愿、凝聚力和心理能力。 | 越高越好。低士气会降低战斗效能，但绝不会自动下令撤退、投降或移动。 |
| **Supply / 补给** | DLC 资源刻度上的弹药、燃料、食物、零件和综合后勤。 | 越高越好。移动、强化工事、建设、炮击和空袭会消耗；不足时行动会被拒绝或暂停。 |
| **Fatigue / 疲劳** | 累积的体力和作业疲劳。 | 越低越好。移动和高强度工作/任务会增加，空闲恢复会降低；高疲劳会削弱战斗和移动战备。 |
| **Supp. / 压制** | 在火力或压力下的即时混乱和行动受限程度。 | 越低越好。会降低战斗/移动战备并减慢工事和设施建设；按 DLC 速率随推演时间衰减。 |
| **Prepared Defense / 防御准备** | 本部队野战工事相对于 DLC 最大堑壕值的百分比。 | Defend/Fortify 会提高；移动会放弃原阵地。 |
| **Fort Cover / 要塞掩护** | 附近已启用盟军设施提供的额外掩护。 | 它来自设施作用区，不是本部队自己的工事条；设施被毁或部队离开范围后消失。 |
| **MOV** | 计算单位数据、地形、战备、姿态和任务后的当前实际移动速度。 | 不是营的理论速度；显示 `0` 表示当前不能移动。 |
| **Altitude / 海拔** | 当前 GIS 高程或安全默认高程。 | DLC 启用相关规则时，会影响视线和战斗。 |
| **Def. Radius / 防御半径** | 编队在地图上的实体/防御占地范围。 | 不是武器射程；射击距离由武器卡和射程分段决定。 |
| **City Influence / 城市影响** | 当前坐标所在城市影响区及强度。 | `None · 0.00` 表示此处没有编写的城市效果。 |
| **Effective Complexity / 有效复杂度** | 地形和城市复杂度的合成值，用于移动、隐蔽、掩护、正面宽度和疲劳。 | 数值通常越大越难行动，但精确系数由 DLC 决定。 |
| **OOB / 战斗序列** | 组成部队的营类型和数量。 | 决定满编、机动/防护数据、能力和挂载武器组。 |
| **Weapon Groups / 武器组** | 从所有营汇总得到的实际挂载武器组。 | 只有角色正确且当前距离落入有效射程分段的武器才贡献火力。 |
| **Armor / Armor Gen** | 实际数值装甲与描述性技术代数。 | 穿甲计算读取 Armor 数值；代数只描述技术，不能代替装甲数值。 |
| **Aircraft Type / 飞机类型** | 空袭单位使用的任务性能档案。 | 决定实际飞行速度、航程、作用区、精度、载荷、成本和防空暴露。 |

士气需要特别说明：自带 DLC 使用百分比式显示。`0–25` 为红色，超过 `25` 到 `50` 为琥珀色，超过 `50` 为绿色。颜色只是警告，不会触发自动撤退或投降。

对于启用士气的单位类型，引擎用 `max(morale_floor, 当前士气) / morale_scale` 乘到战斗效能上；两个参数都来自当前 DLC，所以不同 DLC 的士气效果可以不同。直接战斗和空袭冲击会降低士气；符合恢复条件的待命/防御部队会随推演时间恢复，最高恢复到编成计算出的最大组织度。Reserve 姿态会按核心规则提高恢复速度。

不要混淆两个主席控制：

- **MUN → morale** 会立即加减士气点，并限制在单位允许范围内。
- **Zeus → Morale multiplier** 只在指定时长内改变之后的士气恢复速度，不会立即增加士气。

士气也不等于人数、补给、疲劳或压制；修改其中一项不会暗中改写其他项。

## 七、地图和部队操作

### 选择并查看部队

1. 点击地图上的部队图标。点击空白地图不会选择部队。
2. 右侧面板会显示阵营、状态、人数、士气、补给、疲劳、压制、工事、经纬度、速度、海拔、防御半径、城市影响、地形复杂度、编成、完整武器组以及独立的装甲防护/装甲代数。
3. 在右侧面板内部滚动，找到 **Operational Order（作战命令）** 和可能出现的 **Support Mission（支援任务）**。
4. 直接点击另一支部队即可切换；点击 **Release/释放** 可取消选择。

### 先理解“任务”和“姿态”

- **任务 Task** 决定部队做什么、去哪里：原地待命、转移、规划路线、突击、就地防御、强化工事。
- **战斗姿态 Combat Stance** 决定怎么执行：火力纪律、隐蔽、速度、侦察、恢复、掩护和战斗倍率。
- 改变任务不会改变姿态；改变姿态不会取消任务。
- **转移**和**规划路线**在移动中不主动发起远程攻击，即使当前姿态允许开火；仍保留近距离自卫。
- **停火待命**姿态还会阻止其他任务主动远程开火；同样保留近距离自卫。

### 修改战斗姿态

1. 选择一支部队。
2. 在 **Combat Stance** 下拉框中选择姿态。
3. 阅读界面显示的战斗倍率、速度倍率、掩护和行为摘要。
4. 点击 **Set Stance**。只选下拉选项、不点击按钮不会生效。

| 姿态 | 适合用途 | 代价 |
| --- | --- | --- |
| Aggressive / 积极 | 正常全额战斗力和正常移动。 | 隐蔽性低，没有额外基础掩护。 |
| Defensive / 防御 | 保持正常火力，同时降低暴露并获得保护。 | 没有速度或恢复加成。 |
| Stealth / 隐蔽 | 尽量降低侦测和暴露。 | 半速、战斗力和侦察能力下降；不会自动生成撤退。 |
| Recon / 侦察 | 快速搜索并大幅提高发现能力。 | 更容易暴露，战斗力降低。 |
| Reserve / 预备队 | 加快恢复。 | 移动更慢，战斗力明显降低。 |
| Hold Fire / 停火 | 明确禁止主动远程开火。 | 战斗倍率很低，只保留近距离自卫。 |

### 下达每一种任务

**Hold / 原地待命**

1. 选择部队。
2. 点击 **Hold**，无需点击地图。
3. 路线被清除、部队停止，但当前姿态保留。

**Relocate / 转移**

1. 选择部队，点击 **Relocate**。
2. 在地图上点击一个目的地。
3. 检查虚线路径、坐标和目的地地形。
4. 点击 **AUTHORIZE/授权执行**；点错就点击 **ABORT/终止指令**。
5. 部队沿 GIS 路径移动，途中不主动发起远程交火。
6. 如果本部队已经侦测到敌军，而且敌军威胁区与剩余路径相交，引擎会保留原目的地、自动重算避敌路线；地图和遥测卡会显示 **CONTACT-AVOIDANCE ROUTE**。

临时威胁区由双方编队实体半径、敌军直接射击距离和核心安全余量共同组成，寻路仍会计算地形、公路与河流代价。系统只避开本阵营已知的敌军，不会使用全知信息。避敌代价很高但不是绝对禁止：如果目的地就在威胁区内，或不存在完全安全的路线，部队仍可继续前往，并保留近距离自卫。相同接触不会反复触发重算；新发现的敌军或明显移动后的敌军可在核心冷却时间后再次触发绕行。

**Planned Route / 规划路线**

1. 选择部队，点击 **Planned Route**。
2. 按实际行进顺序点击航点 1、航点 2、航点 3……每次点击都会增加一个编号航点。
3. 检查完整虚线路线。
4. 最后一个航点完成后，再点击 **AUTHORIZE**。DLC 规则会限制最大航点数量。

**Assault / 突击**

1. 选择能够直接地面战斗的部队，点击 **Assault**。
2. 点击最终目标位置。
3. 检查后点击 **AUTHORIZE**。
4. 部队按 DLC 的突击速度倍率推进，并在继续接近时按姿态攻击已侦测敌人。只有已侦测敌军在近距离地面接触中实际阻挡推进时才停止；接触解除后继续前进。

**Defend Here / 就地防御**

1. 让部队位于需要防守的位置。
2. 点击 **Defend Here**，无需点击地图。
3. 部队停止、恢复，并以正常 DLC 速率构筑工事。以后移动会放弃工事。

**Fortify / 强化工事**

1. 选择有足够补给、能够直接战斗的部队。
2. 点击 **Fortify**，无需点击地图。
3. 部队更快构筑工事，同时消耗补给并增加疲劳。压制会降低速度，补给不足会暂停施工。
4. 工事达到上限后，任务自动转为 **Defend Here**。

### 建造和攻击军事设施

军事设施是独立、持久、可摧毁的地图实体，不是部队，也不是 Fortify 的另一个名称。**Fortify** 只为当前部队建立临时野战工事，部队移动后会放弃；**Military Construction** 会建立具有所属阵营、独立图标、建设进度、完整度、装甲、作用半径和存档状态的设施。

建造步骤：

1. 让一支仍有人员的地面战斗部队停在预定位置，然后选中它。
2. 滚动到 **Military Construction**，选择 DLC 定义的类型，例如 **Fortification** 或 **Radar Site**。
3. 阅读工期、总补给成本和效果，点击 **Build at Current Position**。
4. 点击运行。建设部队必须保持在 DLC 设定的工作半径内并处于 `CONSTRUCTING` 状态。施工消耗补给、增加疲劳；压制会减速，低于补给阈值会暂停。
5. **Hold**、移动或支援任务会暂停施工，但不会删除工地。让原建设部队返回，选择相同类型并点击 **Resume Construction** 即可继续。
6. 进度达到 100% 后设施启用。如需重启后保留，必须手动保存检查点。

模板的 Fortification 会为作用半径内盟军增加掩护；Radar Site 会按概率发现射程内敌方部队和军事设施。设施被摧毁后所有效果立即停止，但残骸仍显示在地图和委员会记录中。

攻击设施时，先选中有能力的敌对部队，点击 **Assault**、**Bombard Area** 或 **Launch Airstrike**；目标选择提示开启后，点击设施的菱形图标并授权。直接射击需要接触或近距离，并读取 `direct_fire` 武器射程分段；炮击只用间接 `bombard` 武器；空袭读取机型和 `airstrike` 武器。结算针对设施在 DLC 中定义的软目标比例、装甲、地形保护和各攻击方式易损倍率，不会把设施伪装成“有人员的部队”。

### 炮击和空袭

只有 DLC 单位类型、营级编成或部队自身能力包含对应能力时，右侧才会显示支援任务卡。

1. 选择有能力的炮兵或空军单位。
2. 阅读卡片中的射程、效果半径、时长/资源成本和 READY/阻止原因。
3. 点击 **Bombard Area** 或 **Launch Airstrike**。
4. 地图会显示最大范围。点击目标坐标。
5. 检查距离和效果圈。目标超出范围时 **AUTHORIZE** 会被禁用。
6. 点击 **AUTHORIZE**。

炮击会取消旧移动路线，在 DLC 设定时长内持续消耗补给。空袭在起飞时就扣除补给并增加疲劳，即使未命中也不返还；飞机途中会受到防空威胁，投弹后返回记录的基地。两种区域任务都可能以较低的 DLC 设定精度命中尚未侦测到的敌军。同一支部队不能同时执行两个支援任务；必要时可用 **Hold** 终止当前任务。

空袭伤亡采用“区域暴露”模型：引擎先根据飞机类型的作用半径估算目标编队有多少人员位于作用区内，再按该机型的软/硬目标能力、目标编成、飞机战备、精度、载荷和目标掩护计算。`strike_power_reference` 校准武器威力，`casualty_coefficient` 决定暴露人员中的杀伤率，`maximum_casualty_fraction` 限制一次出动对每支编队造成的最高损失。Test DLC 的红方攻击战斗机对有准备的 12,000 人合成军实施一次已侦测空袭时仍约造成一千人损失，但重型轰炸机、近距支援机和隐身打击机现在会得出明显不同的结果。飞行员和地勤人数不会被当作弹药威力倍增。战果会分别报告人员损失、持续士气冲击和临时压制。陆军、炮兵以及停在基地的空军都可成为对地空袭目标；正在出击或返航的空军属于空中目标，不进入对地打击结算。执行空袭的飞机只进入空袭与防空结算，不参与地面直接交火。炮兵单位只要其 DLC 单位类型速度大于零即可执行 Relocate；速度零只应用于有意设置的固定炮位。

每支具备空袭能力的部队都引用 DLC 中的 `aircraft_type`。机型会改变飞行速度、航程、作用半径、软/硬目标专长、精度、载荷、士气冲击、压制、补给/疲劳成本和防空易损性。控制面板和地图目标圈显示的都是当前机型的实际数值。

| Test DLC 空军 | 飞机类型 | 主要特点 |
| --- | --- | --- |
| 红方 | 攻击战斗机 | 快速精确遮断，偏重硬目标 |
| 蓝方 | 重型轰炸机 | 远程大范围重载荷，但成本和防空暴露更高 |
| 绿方 | 近距空中支援机 | 短程对地支援和强压制，但更容易受防空威胁 |
| 金方 | 隐身打击机 | 快速、精确、防空暴露低，但打击范围较小 |

单位面板中的 **Personnel Alive（现存兵力）** 是战斗和任务伤亡结算后的当前存活人数。部队归零、地图图标、委员会汇总、手动存档、空投结果和 Zeus 人数修改都使用同一个权威数值。战备状态保持独立：补给、疲劳、压制、士气、地形、正面宽度、姿态和掩护只影响效能，不会暗中改写存活人数。

士气只影响战斗效能，绝不会自动生成撤退目的地。任何撤退或重新部署都必须由主席明确下达转移、规划路线或突击任务。

## 八、使用“空投”部署新部队

1. 如果不是故意实时增援，先暂停。
2. 点击 **空投**。
3. 在 **Unit Callsign** 输入清楚的部队名称。
4. 在 **Faction Designation** 输入准确阵营名。拼写和大小写会影响外交、报告和政治记录。
5. 选择 DLC 定义的 **Unit Type**，阅读能力提示。
6. 若选择了具备空袭能力的单位类型，再选择 **Aircraft Type** 并阅读任务性能说明。
7. 在 **Order of Battle** 中至少把一种营的数量设为 `1`。界面会根据营的 `size` 自动计算满编人数，并显示由这些营生成的武器组。
8. 确认武器组包含单位所需的 `direct_fire`、`bombard` 或 `airstrike` 角色。切换单位类型时，界面会在可能时选择兼容的初始营。
9. **Deployed Personnel** 可保留满编人数，也可降低为欠编人数，但必须大于 `0`。
10. 点击 **Select Drop Zone on Map**。
11. 在地图上点击一次投放位置。成功后面板关闭，地图居中并自动选中新部队。

若没有反应，请检查：名称和阵营不是空白、至少选择一个营、人数大于零，并确认界面是否正在等待你点击地图。

## 九、Zeus 主席控制台

Zeus 的修改立即影响当前运行状态，但绝不会自动保存。

1. **临时部队效果**：先在地图选中部队，选择 Combat/Speed/Morale，输入倍率和正的推演小时，然后应用。`1.0` 不变，`1.2` 增加 20%，`0.8` 减少 20%。Combat 乘战斗效能，Speed 乘移动速度，Morale 乘待命/防御时的士气恢复速度；Morale 选项不会立即增加士气点。
2. **立即设定部队兵力**：先选中部队，输入大于等于 `0` 的整数，点击 **Set personnel**。不会改变编成、装备、补给或士气；设为 `0` 会让该部队无有效兵力。
3. **城市影响区**：选择已有城市或点击 **New**。填写安全 ID、名称、经纬度、非负面积和 `0` 到 `1` 的影响率，然后保存。删除需要确认。
4. **省份政治与民意**：选择已有记录或点击 **New**。填写与地图完全一致的省名、准确阵营名、`-1` 到 `+1` 的民意、`0` 到 `1` 的占领度，然后保存。推演时间推进时，军事存在会改变占领。达到阈值的敌对阵营会造成争夺；盟友不会互相争夺。
5. **外交关系**：输入两个不同的准确阵营名。**Mark as allied** 建立双向同盟；**Mark as hostile** 移除同盟，但不会自动命令双方攻击。

## 十、在 MUN 面板录入危机裁定

1. 如果效果需要在确定时刻生效，先暂停。
2. 点击 **MUN**，查看委员会简介、交战规则、代表角色和阵营战备。
3. 输入简短标题和清楚的裁定正文。
4. 若只影响一个阵营，输入准确阵营名；若影响全部单位，使用 DLC 的全局选择器，模板默认是 `GLOBAL`。
5. 选择效果：
   - `none`：只记录，不改变单位数值。
   - `morale`、`supply`、`fatigue`：立即加上输入值；负数表示减少。
   - `combat_modifier`、`speed_modifier`：在指定推演小时内应用非负倍率；`1.0` 不变，`1.2` 为 +20%，`0.8` 为 −20%。
6. 输入大于零的持续小时。临时倍率会使用它；所有裁定记录也会保存该时长。
7. 公开更新保持勾选 **Publish to delegate-facing crisis feed**；主席团内部记录取消勾选。
8. 只点击一次 **Apply Adjudication**。在公开更新列表和实时情报中检查结果。
9. 点击 **Export SITREP** 下载 Markdown 格式报告。界面导出包含阵营状态和公开更新。若主席团需要包含内部记录的版本，在 DLC 已挂载时打开 `/api/committee/sitrep?private=1`。

危机裁定不会建立检查点。重要裁定后必须手动保存。

### SITREP 到底是什么、表示什么

**SITREP** 是 **Situation Report（态势报告）**。它是在点击导出的那一刻，对当前推演状态生成的文字快照，用于向主席团、危机工作人员、代表或下一场会议说明目前局势。

报告包含：

- 委员会/剧本名称和当前推演时间；
- 每个阵营的现存总人数；
- 该阵营的单位记录数量；
- 这些单位记录的简单平均士气和平均补给；
- 已启用、建设中和已摧毁的军事设施数量；
- 通过 MUN 面板录入的危机更新。

例如 `FACTION_A: 8500 living personnel, 6 units, morale 72%, supply 64%; military sites 2 operational, 1 under construction, 0 destroyed` 表示：该阵营当前六条编队记录共有 8,500 名存活人员；这六条记录的士气简单平均为 72、补给简单平均为 64；并拥有所列设施状态。平均值按“单位记录”平均，不按人数加权：100 人单位和 10,000 人单位各贡献一个数值。

普通 **Export SITREP** 按钮只包含标记为公开的记录。需要同时包含公开和主席团内部记录时，在 DLC 已挂载期间打开 `/api/committee/sitrep?private=1`，并安全保存返回的 Markdown 文本。

SITREP **不会**：

- 保存或恢复推演；
- 自动宣布胜者或判断胜利条件是否完成；
- 包含地图图片、每支部队的全部命令或完整伤亡历史；
- 因为信息进入报告，就自动变成可以公开给代表的内容。

需要恢复进度时用 **存档**；需要传达当前局势时用 SITREP。导出报告不会建立或更新检查点。

## 十一、存档、恢复、重置和切换 DLC

- 界面只有三个手动槽：检查点 1、2、3。
- **保存到此处** 写入当前状态。已有内容时会要求确认覆盖。
- **恢复此检查点** 会要求确认、替换当前状态，并保证推演处于暂停。
- **重置剧本** 会丢弃当前实时进度，返回 DLC 编写的初始状态，不会自动备份。
- 挂载任何 DLC 都会加载其初始状态，不会自动打开旧存档。正确顺序是：先保存当前工作 → 挂载目标 DLC → 手动恢复兼容检查点。
- 检查点同时绑定 DLC ID 和规则版本，不兼容的存档无法恢复。
- 文件位于项目根目录，名称为 `save_slot_1.json`、`save_slot_2.json`、`save_slot_3.json`；战斗日志也在项目根目录。
- 兼容存档包括任务、路线、野战工事、飞机档案和任务状态、军事设施及施工进度、城市、省份政治、外交、部队/设施侦测、临时效果、委员会记录和日志。

**系统完全没有自动存档。**下达命令、空投、Zeus 修改、MUN 裁定、外交修改、剧本重置、关闭浏览器或停止服务器都不会自动保存。

### 第一次正式使用前的完整练习

1. 启动服务器，确认 `/status` 显示 ready。
2. 打开主界面，挂载一个有效练习 DLC，确认处于暂停。
3. 打开 **存档**，把完全未修改的初始状态保存到检查点 1。
4. 选择一支仍有人员的部队，按照上方表格逐项读懂遥测数据。
5. 修改姿态，然后点击 **Set Stance**。
6. 点击 **Relocate**，在附近点击目的地，检查路线，再点击 **AUTHORIZE**。
7. 点击 **运行** 几秒钟，然后点击 **暂停**；确认推演时钟和部队坐标发生变化。
8. 如果该部队有支援或建设控制，打开并阅读 READY/阻止原因；不要授权不打算执行的操作。
9. 打开 **MUN**，录入一条无害测试更新，效果选择 `none`，保持公开，只应用一次。
10. 导出 SITREP，用文本编辑器打开下载的 `.md`；确认时间、阵营汇总、设施和测试更新都存在。
11. 把改变后的状态保存到检查点 2。
12. 恢复检查点 1，确认推演暂停，而且测试移动/裁定从实时状态消失。
13. 恢复检查点 2，确认改变后的状态重新出现。
14. 熟悉后再重置练习剧本。绝不要在真实委员会唯一一份状态上做这套实验。

## 十二、DLC 必须满足的要求

### 用最直白的话说明

一个 DLC 只有同时满足以下条件才能游玩：

- 它是 `dlc` 目录下一层的普通文件夹，例如 `dlc/my_crisis`。
- 文件夹名只能使用字母、数字、`_`、`-`、`.`；需要在挂载列表显示时，名称不能以 `_` 开头。
- 文件夹内必须有五个可读取、根节点为 JSON 对象的文件：`scenario.json`、`rules.json`、`units.json`、`battalions.json`、`weapons.json`。
- `scenario.json` 必须有剧本名、委员会对象、外交列表、完整地图配置，并正确指向单位和规则文件。
- `rules.json` 必须使用 `schema_version: 1`，保留 `_template` 的所有剧本规则区段，且不得包含 `orders` 或 `stances`；这两个属于核心规则。
- 至少有一个武器和一个营种；浏览器制作器还要求至少一个初始单位。
- 每个 ID 安全且唯一；每个单位引用存在的单位类型、核心姿态和营种；可选显示用 `primary_weapon` 必须由该编成实际挂载。
- 所有必填数字必须是有限数值并位于允许范围。`NaN`、无穷大、用字符串伪装的数字、负人数、大小为 0 的营和越界坐标都会被拒绝。
- 所有配置路径必须是 DLC 内部的相对路径。绝对路径和 `..` 跨目录路径会被拒绝。

`maps` 文件夹以及所有 GIS 文件都是可选内容。缺少可选地图包不会让 DLC 无效，只会启用安全默认规则。

### 目录结构

```text
dlc/my_committee/
├── scenario.json          必须
├── rules.json             必须，schema_version 1
├── units.json             必须，可为对象形式的初始单位表
├── battalions.json        必须，至少一种营
├── weapons.json           必须，至少一种武器
└── maps/                  整个目录可选
    ├── dem_tiles/         可选 GeoTIFF 高程瓦片
    ├── roads.tif          可选道路栅格，也可使用 GeoJSON
    ├── rivers.geojson     可选河流线
    └── provinces.geojson  可选省界多边形
```

### 安装别人发来的 DLC ZIP

1. 暂停并保存当前委员会。
2. 在黑色窗口按 `Ctrl+C` 停止服务器。
3. 如果 ZIP 来自他人，先进行安全扫描，然后解压。
4. 找到**直接包含 `scenario.json`** 的文件夹。不要形成 `dlc/my_crisis/my_crisis/scenario.json` 这种多一层目录的错误结构。
5. 把该文件夹移动到项目的 `dlc` 目录。
6. 重命名为安全 ID，例如 `security_council_1986`，不要以 `_` 开头。
7. 启动服务器，打开 `/status`，修复全部验证错误。
8. 打开主界面挂载。服务器会先完整构造并验证新剧本，成功后才停止旧推演心跳。

## 十三、每个 DLC 文件负责什么

### `scenario.json`

负责剧本身份、地图、委员会、外交、城市、省份初始政治和文件引用。重要字段：

- `scenario_name`：非空剧本名称。
- `description`：主席可读简介。
- `map_center`：`[纬度, 经度]`，注意顺序不是经纬度。
- `map_zoom`：`0` 到 `20`。
- `initial_units_file`：通常为 `units.json`；省略时加载器默认使用该名称。
- `simulation_rules_file`：通常为 `rules.json`。
- `map_config.bounds`：`min_lon < max_lon`、`min_lat < max_lat`；经度 `-180..180`、纬度 `-90..90`。
- `grid_resolution`：两个 `16..4000` 的整数。
- `dem_analysis_resolution`：两个 `16..8000` 的整数。
- `fallback_elevation_m`、地形成本参数和完整 `pathing`：必须是有效数值。
- `dem_dir`、`dem_file`、`roads_file`、`rivers_file`、`provinces_file`：可为空；非空时必须是 DLC 内安全相对路径。
- `province_name_property`：省界 GeoJSON 中保存省名的属性字段。
- `committee`：委员会名称、类型、范围、日期、主席/代表可见性、公开简报、交战规则、代表角色、胜利条件和主席备注。
- `diplomacy_blocs`：同一 bloc 中的成员初始互为盟友。
- `cities`：每项需要安全唯一 ID、名称、有效坐标、非负面积和 `0..1` 影响率。
- `province_politics`：每个“省份—阵营”组合只能一条；民意 `-1..1`，初始占领 `0..1`。
- `military_installations`：可选的初始要塞、雷达站或未完工项目列表；每项需要安全唯一 ID、有效类型、名称、阵营、坐标、完整度和 `0..1` 建设进度。

所有路径必须留在 DLC 文件夹内，不能通过配置读取电脑任意文件。

### `rules.json`

必须使用 `schema_version: 1`。它负责剧本特有的数值和特殊机制；不得保存核心 `orders` 和 `stances`。从 `_template` 开始时，不要删除任何区段。

| 区段 | 负责内容 |
| --- | --- |
| `clock` | 默认/最小/最大速度、心跳、真实时间与推演时间换算 |
| `resources` | 士气、补给、疲劳、压制的范围 |
| `state_limits` | 日志、委员会记录、SITREP 和状态流保留数量 |
| `unit_defaults` | 默认单位类型、姿态、资源、状态和临时效果 |
| `footprint` | 人数到地图半径的换算 |
| `composition` | 编成统计和最低组织度 |
| `unit_types` | 单位图标、非进攻统计来源、能力、地形、战斗资格、正面宽度和侦测 |
| `readiness` | 补给、疲劳、压制、士气对战斗和移动的影响 |
| `recovery` | 静止恢复、压制衰减和工事 |
| `movement` | 抵达距离、最大航点、疲劳和补给消耗 |
| `defense` | 防御/强化速度、成本、补给阈值、压制惩罚 |
| `detection` | 可见度、距离概率、接触记忆和状态可见度 |
| `tactical_support` | 友军支援能力的范围与条件 |
| `political_influence` | 分阵营军事存在、占领增减、控制和争夺阈值 |
| `combat` | 掩护、武器化直接射击、正面宽度、穿甲和高差 |
| `missions` | 炮击、飞机类型空袭配置和防空 |
| `military_installations` | 建设施工规则、完整度伤害系数以及 DLC 定义的设施类型与效果 |
| `geography` | 视线和寻路使用的能力名称 |
| `directives` | MUN 裁定允许的效果与默认值 |
| `modifiers` | Zeus 临时效果类型、数值和时长范围 |

单位类型的 `stats_source` 可为 `composition`（从营编成计算）或 `fixed`（读取 `fixed_stats`），但它只决定速度、防御、突破、组织度、装甲、软目标比例和地形等非进攻统计。软/硬攻击、穿甲、射程、武器代数和任务资格始终来自营所挂载的武器。能力名称用于把数据接到通用引擎行为，例如 `bombard`、`airstrike`、`air_defense`、`tactical_support`、`river_engineer`、`heavy_river_crossing`。如果在规则中改名，单位或营的能力列表必须同步使用完全相同的名字。

所有进攻火力都以 `weapons.json` 为唯一来源。单位按“营数量 × 每营武器组数量”汇总武器编成，不再用总人数把同一份火力重复放大；当前可用人员和地形限制的战斗正面只会降低能够开火的武器组比例。每件武器按实际交战距离选中第一个适用的射程分段，超出最后一段则不贡献火力。软/硬攻击按目标软硬比例加权，穿甲失败只削弱该武器的硬目标部分。炮击只使用同时标记为间接射击和 `bombard` 的武器。武器代数属于武器，装甲防护与 `armor_generation` 则独立属于营；实际显式攻击、穿甲和装甲数值决定计算，代数作为清晰的技术资料显示。

飞机类型数据位于 `rules.json → missions.airstrike.aircraft_types`。顶层的 `sortie_range_km`、`blast_radius_km`、`supply_cost` 和 `fatigue_cost` 是剧本基准；每种机型再提供以下倍率：

- 飞行：`cruise_speed_multiplier`、`sortie_range_multiplier`；
- 打击范围与投送：`blast_radius_multiplier`、`accuracy_multiplier`、`unobserved_targeting_multiplier`、`payload_multiplier`；
- 目标专长：`soft_target_multiplier`、`hard_target_multiplier`；
- 次生效果：`morale_shock_multiplier`、`suppression_multiplier`；
- 运用与生存：`supply_cost_multiplier`、`fatigue_cost_multiplier`、`aa_vulnerability_multiplier`。

`default_aircraft_type` 仅用于现场新建空军和兼容旧存档。`units.json` 中每支初始空袭单位都必须明确写出有效 `aircraft_type`，避免不同空军无意中共用同一套性能。

`rules.json → military_installations` 分三部分：`construction` 设置工作半径、补给阈值、疲劳、压制减速、设施间距和每支建设部队的项目上限；`damage` 把直接射击、炮击、空袭武器威力转换为设施完整度伤害，并处理地形保护；`types` 定义名称/图标、工期、补给成本、最大完整度、装甲、软目标比例、可见度、不同攻击方式易损倍率、要塞掩护和雷达性能。核心只保存通用建设、侦测、伤害和存档流程，具体战役数值和特殊设施效果仍全部属于 DLC。

### `battalions.json`

每种营必须有非空名称、能力字符串列表、武器组对象和以下数值：

- `size`：至少 `1` 的整数满编人数；空投人数估算依赖它。
- `speed`、`armor`、`defense`、`breakthrough`、`org`、`terrain`：非负有限数。
- `armor_generation`：与装甲防护分开保存的非负整数。
- `weapons`：武器 ID 到“每营抽象武器组数量”的对象；每个数量必须大于 `0`。营内不得再写 `soft`、`hard` 或 `ap`。
- `softness`：`0..1`。
- `recon_power`：有限数，可以为负。
- `movement_supply_cost`：非负有限数。
- `capabilities`：非空能力名组成的列表，也可以是空列表。

### `weapons.json`

每种武器必须有：

- 非空显示名称 `name`；
- 非负整数武器代数 `generation`；
- 明确布尔值 `indirect_fire`。`true` 表示没有直接地形视线也可射击；射程长不会自动获得间接射击能力；
- 非空 `roles`，只可使用 `direct_fire`、`bombard`、`airstrike`；`bombard` 武器必须是间接射击；
- 非空 `range_bands`，按 `max_range_km` 严格递增。每段分别给出 `soft_attack`、`hard_attack`、`armor_piercing`，超过最后射程不产生火力。

### `units.json`

每个初始单位的 ID 必须安全唯一。需要：

- 非空 `name` 和 `faction`；
- 非负 `personnel` 和 `equipment_level`；
- 有效 `lon`（`-180..180`）和 `lat`（`-90..90`）；
- `unit_type` 引用 `rules.json → unit_types`；
- 具备空袭能力的单位必须用 `aircraft_type` 引用 `rules.json → missions.airstrike.aircraft_types`；
- `stance` 引用 `doctrine.py` 的核心姿态；
- `composition` 中每个键引用存在的营，数量非负；
- 可选 `primary_weapon` 只控制显示偏好，必须确实由该编成的营挂载；省略时由引擎自动选择主要武器；
- 可选 `capabilities`、士气、补给、疲劳、压制、工事和已保存任务。

固定统计单位可以从 `fixed_stats` 读取移动和防御等数据，但进攻火力仍必须来自营的武器组。

## 十四、用浏览器编辑器制作 DLC

编辑器只把未导出的工作保存在当前浏览器页面内。刷新或关闭页面会丢失编辑内容。复杂剧本制作过程中应定期导出中间 ZIP。

1. 启动服务器，打开 `/editor`。
2. 等待中性模板自动加载。**Load Crisis Template** 会在确认后清空当前编辑数据，并重新读取 `dlc/_template`。
3. **2. Scenario & Map**：
   - 填剧本名、简介；地图中心顺序为纬度、经度。
   - 边界最小值必须小于最大值。
   - 不理解性能影响时，保持模板网格和 DEM 分析分辨率。
   - Province Name Property 必须与 GeoJSON 的省名字段完全一致。
   - DEM 可多选 `.tif/.tiff`；道路可用栅格或 GeoJSON；河流、省界用 GeoJSON/JSON。
   - 城市 ID 唯一安全，面积非负，影响率 `0..1`。
   - 每个省份—阵营初始政治记录必须唯一，名称必须与地图和部队拼写一致。
4. **3. Simulation Rules**：
   - 不熟悉公式时只修改上方普通字段。
   - Advanced Rules JSON 是完整剧本规则；保持 schema 1，不删除模板区段。
   - 可在此增加单位类型、能力和详细系数，但不得加入 `orders` 或 `stances`。
   - 修改文本后必须点击 **Apply Advanced JSON**，否则导出数据不会更新。
5. **4. Committee**：填委员会身份、开始日期、可见性、公开简报、交战规则、代表角色与私密简报、胜利条件、主席备注。
6. **5. Diplomacy**：把初始盟友放进同一个 bloc；成员用逗号分隔，拼写与单位阵营完全一致。
7. **7. Battalion Types**：先定义营。分别填写装甲防护和装甲代数，再为每营分配正数武器组；`size` 为正整数，`softness` 为 `0..1`，移动补给成本非负，侦察值可为负。
8. **8. Weapons**：定义武器代数、任务角色和由近到远的射程分段；每段分别填写软攻、硬攻和穿甲，并明确勾选或取消间接射击。
9. **6. Units**：至少建立一个初始单位；填安全唯一 ID、阵营、坐标、人数、装备、单位类型、核心姿态和营数量。武器编成由营自动生成；删除仍被引用的营/武器会让包无效。
10. **9. Military Targets**：加入剧本开始时已经存在的设施，也可以保持空列表，让玩家在推演中建设。未完工项目如需继续施工，应指定一个已存在的建设部队。
11. 点击 **Check Package**，修复每一个 `FIX`。浏览器检查只是初筛，服务器 `/status` 才是最终验证。
12. 点击 **Export DLC Zip**。JSZip 当前来自 CDN，所以默认导出需要网络。
13. 在下载目录解压 ZIP。
14. 把直接包含五个 JSON 的文件夹移动到 `CDC Sim\dlc\<safe_id>\`。
15. `<safe_id>` 只用字母、数字、下划线、连字符或点；可玩剧本不要以 `_` 开头。
16. 打开 `/status`，修复所有服务器验证错误。
17. 挂载并检查所有单位、军事设施和地图功能，做短时间测试，然后重置剧本并建立干净的检查点 1。

手动制作时，应复制整个 `dlc/_template` 文件夹并重命名副本，再用 UTF-8 编辑器修改五个 JSON。不要为了制作一个剧本直接修改 `_template`，因为浏览器编辑器把它当作中性起始模板。

## 十五、可选 GIS 文件与默认规则

大体积 `.tif/.tiff` 文件被 `.gitignore` 排除，因此从 Git 获取项目时通常不会自动包含高程和道路栅格。`afghan` 仍可挂载；缺少数据时使用：

- 无高程：全部使用 `fallback_elevation_m` 的平坦地形，不产生高程视线遮挡。
- 无道路：所有位置使用普通地形移动成本。
- 无河流：不计算渡河惩罚。
- 无省界：位置显示 Unknown/Unmapped，不绘制省份政治颜色。

如果需要真实 GIS 效果：

1. 把文件放到 DLC 自己的 `maps` 目录。
2. 在 `scenario.json → map_config` 中使用 DLC 内相对路径。
3. 高程/栅格应覆盖剧本边界并使用经纬度地理坐标；省界属性必须包含正确省名字段。
4. 重启并挂载，在左上 GIS 面板确认对应项目为 `ON`。

## 十六、局域网使用和安全警告

默认服务器只监听 `127.0.0.1`，只有本机能访问，这是最安全的模式。

如确实需要在可信局域网开放，在项目目录打开 PowerShell：

```powershell
$env:CDC_HOST = "0.0.0.0"
$env:CDC_PORT = "5000"
.\.venv\Scripts\python.exe server.py
```

然后：

1. Windows 防火墙询问时，只允许需要的 **专用网络**。
2. 在主席电脑运行 `ipconfig`，找到 IPv4 地址，例如 `192.168.1.50`。
3. 同一可信网络上的其他设备打开 `http://192.168.1.50:5000`，替换为实际地址。
4. 委员会前从另一台设备完整测试。
5. 结束后按 `Ctrl+C`。上述环境变量只影响当前 PowerShell 窗口。

本系统没有登录、身份验证、HTTPS、CSRF 防护或角色权限。任何能访问服务器的人都能使用主席控制并修改推演。不要做端口转发，不要放在公共 Wi-Fi，不要暴露到公网。预期部署方式是可信私网中的一台主席电脑。

## 十七、手动安装、修复、测试和卸载

批处理无法运行时，在项目目录打开 PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe server.py
```

不需要先激活虚拟环境；直接调用 `.venv\Scripts\python.exe` 能保证使用正确解释器。

运行完整回归测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

修复依赖：再次运行 `INSTALL_OR_REPAIR.bat`。如果必须重建环境，先停止服务器并保留 DLC/存档，只删除项目内的 `.venv`，再运行安装脚本。不要把删除整个项目当成普通修复方法。

卸载：停止服务器，备份自制 DLC、`save_slot_*.json`、战斗日志和 SITREP 后，删除项目文件夹即可。安装脚本不会建立 Windows 服务，也不会全局安装 CDC Sim。

## 十八、常见问题

### 安装脚本一打开就失败

在命令提示符运行 `py -0p`，必须看到 Python 3.12。若没有，安装 64 位 Python 3.12 并启用 Launcher/PATH，重新打开目录再运行。电脑里只有 Python 3.14 不等于满足要求。

### 出现 `No matching distribution found` 或 NumPy/Pillow/Rasterio 错误

通常是 Python 版本或位数错误。运行 `.venv\Scripts\python.exe --version`，必须是 3.12.x。32 位 Python 或 3.13/3.14 可能没有匹配锁定依赖的 wheel。只删除未完成的 `.venv`，安装正确的 64 位 3.12，再运行修复脚本。

### 浏览器显示无法访问网站

- 黑色启动窗口必须保持开启。
- 等待服务器启动文字出现。
- 使用 `http://127.0.0.1:5000`，不要误写成 `https://`。
- 若提示端口已使用，关闭占用 5000 的程序，或设置另一个 `CDC_PORT` 并在网址中使用同一端口。
- 安全软件可能拦截 Python；只允许所需的本地/专用网络权限。

### 界面打开但地图是空白

页面框架来自本机，但 Leaflet 和底图来自外部 CDN。检查网络和浏览器内容拦截。外部底图失败不代表单位和后端推演数据不存在。

### DLC 没出现在列表

- 文件夹名不能以 `_` 开头。
- 必须直接放在 `dlc` 下一层。
- 不能多套一层解压目录。
- 打开 `/status` 阅读验证错误。
- 确认 `scenario.json` 指向正确的 `rules.json` 和 `units.json`。

### 旧 DLC 被拒绝

schema 1 现在要求：完整 `rules.json`；`scenario.json` 中的 `simulation_rules_file`；完整地图地形/pathing 参数；每个武器的 `indirect_fire`；每个营的正整数 `size`、有限 `recon_power` 和非负 `movement_supply_cost`；有效单位类型和核心姿态；完整防御区段；并且旧规则文件不能包含 `orders`/`stances`。最安全的迁移方式是从当前 `_template` 复制，再逐项搬入剧本数据。

### 地形总是平原

先看左上 GIS 面板。可选文件未安装时使用默认平原是正常行为。若显示红色，检查 Rasterio、相对路径、文件存在性、经纬度坐标系和覆盖范围。

### 点击命令后好像没反应

- 转移、规划路线、突击、炮击、空袭和空投都会进入目标模式；下一步是点击地图。
- 选择战术目标后还必须点击 **AUTHORIZE**；修改姿态还必须点击 **Set Stance**。
- 在右侧部队面板内向下滚动，支援任务可能位于屏幕外。
- 阅读弹窗和实时情报。射程、补给、能力、人数、单位类型或已有任务都可能导致拒绝。

### 空投部队不出现

- 至少选择一个 `size > 0` 的营。
- 实际人数必须大于零。
- 名称和阵营不能为空。
- 点击“选择空投坐标”后，还要点击地图。
- 不要忽略 HQ Rejected 错误信息。

### 重启或切换 DLC 后进度消失

未手动保存时，这是预期行为。挂载正确 DLC，打开 **存档**，恢复兼容检查点。系统没有自动存档，挂载也不会自动恢复。

### 编辑器无法导出 ZIP

JSZip 当前来自外部 CDN。确认联网后刷新编辑器。即使 ZIP 导出失败，后端 DLC 验证仍可正常工作。

## 十九、项目结构

| 路径 | 作用 |
| --- | --- |
| `server.py` | Flask 页面/API、输入验证和挂载生命周期 |

| `installations.py` | 持久军事设施模型、建设状态、完整度和序列化 |
| `doctrine.py` | 所有剧本共享的任务、姿态和交互规则 |
| `gis.py` | 高程、地形、道路、河流、寻路和省份 |
| `dlc_loader.py` | 安全路径和完整 DLC/规则验证 |
| `templates/` | 主界面、编辑器、状态页和主席指南 |
| `static/` | 浏览器逻辑和样式 |
| `dlc/_template/` | 中性 schema 1 模板 |
